## Результат

React-приложение «Задачи на React»: список задач с названиями категорий, создание и редактирование с проверкой полей, переключение статуса и удаление с подтверждением, совместные поиск/фильтры статуса, приоритета и категории, общая статистика и число найденных записей, отдельное пустое состояние. Данные находятся в памяти текущей страницы: перезагрузка восстанавливает исходный набор из 12 задач и начальные фильтры варианта 8. Это ожидаемое поведение ПР7, а не ошибка: сервер и localStorage в работу не входят.

## Компоненты и состояние

`App` — владелец `tasks`, `filters` и `editingId`. `TaskForm` — владелец черновика `draft`, ошибок `errors` и сообщений. `categories` импортируются как справочник из `data.js`.

Данные идут вниз через props (`tasks`, `filters`, `stats`, `initialTask`), действия поднимаются вверх обратными вызовами (`onToggle(id)`, `onEdit(id)`, `onDelete(id)`, `onSave(value)`, `onChange(nextFilters)`). Дочерние компоненты не меняют полученные props.

`visibleTasks = selectTasks(tasks, filters)` и `stats = getTaskStats(tasks)` вычисляются прямо при рендере — отдельных состояний для производных данных нет, иначе их пришлось бы синхронизировать после каждого действия. Статистика считается по полному набору, а не по выборке.

Все изменения неизменяемые: `addTask` возвращает `[...tasks, {...}]`, `updateTask`/`toggleTask` — новый массив через `map` с новым объектом, `removeTask` — `filter`. Следующий id берётся как максимум полного массива плюс 1 внутри функционального обновления `setTasks(previous => ...)`; длина массива и максимум видимой выборки не используются (id в наборе разреженные).

Форма пересоздаётся при смене редактируемой записи через `key={editingId ?? 'new'}`: локальное состояние `useState` инициализируется заново из нового `initialTask`, поэтому черновик предыдущей задачи не переносится. После успешного создания форма очищает черновик сама; после успешного редактирования `App` возвращает `editingId` в `null`. При `onSave === false` введённые данные сохраняются.

`window.confirm` вызывается в обработчике до `setTasks`: функции обновления состояния должны быть чистыми, а `StrictMode` в разработке может вызвать их повторно.

## Контрольные вопросы

1. **Чем JSX отличается от строки HTML?** JSX — описание React-элементов, компилируется в вызовы, а не в разметку-строку: используются `className`, `htmlFor`, выражения в `{}`, обязательные закрытые теги. React сам создаёт и обновляет DOM.
2. **Чем props отличаются от состояния?** Props приходят от родителя и не изменяются компонентом; состояние принадлежит компоненту, меняется через `setState` и вызывает повторный рендер.
3. **Почему обычная переменная не заменяет `useState`?** Функция-компонент вызывается заново при каждом рендере, локальная переменная создаётся заново; `useState` сохраняет значение между вызовами.
4. **Когда нужна функциональная форма обновления?** Когда новое значение зависит от предыдущего (`setTasks(previous => ...)`); она же защищает от потери нескольких последовательных обновлений.
5. **Почему нельзя менять объект внутри поверхностной копии массива?** Копия массива хранит те же ссылки на объекты; мутация изменит и «старое» состояние, и React может не увидеть замену. Нужно создавать новый объект: `{ ...task, completed: !task.completed }`.
6. **Зачем стабильный `key` и почему не индекс?** Key связывает элемент с его DOM и состоянием при удалении/перестановке. Индекс меняется при удалении, и React переиспользует не тот узел. Здесь id разреженные (1, 4, 7 … 34), индекс вообще не совпадает с id.
7. **Почему выборка и статистика не в отдельных состояниях?** Они вычисляются из `tasks` и `filters`; отдельное состояние пришлось бы синхронизировать вручную после каждого действия, что даёт расхождения.
8. **Как дочерний компонент сообщает родителю о действии?** Через функцию в props: `onToggle(task.id)`, `onSave(value)`. Дочерний не меняет состояние родителя напрямую.
9. **Что делает поле управляемым?** `value` из состояния плюс `onChange`, строковое начальное значение (не `undefined`); для checkbox — `checked`.
10. **Почему `categoryId` из `select` требует преобразования?** HTML возвращает строку (`"2"`), а схема задачи требует число. `parseInt` принял бы `'2x'` как 2, поэтому используется `/^[1-9]\d*$/` + `Number` + проверка существования категории и `Number.isSafeInteger`.
11. **Как меняется состояние формы при изменении ключа?** React размонтирует старый экземпляр и монтирует новый, локальный `useState` инициализируется заново — черновик и ошибки сбрасываются.
12. **Почему подтверждение удаления не внутри функции обновления?** Функция обновления должна быть чистой: `StrictMode` может вызвать её дважды, и диалог появится дважды (как и повторное вычисление id). Подтверждение выполняется до `setTasks`.
13. **Как отличить отсутствие задач от отсутствия совпадений?** `TaskList` сравнивает `total === 0`: пустой набор даёт «Задач пока нет. Создайте первую.», непустой набор при пустой выборке — «По выбранным условиям задач нет.».
14. **Что проверяет `npm test` и чего не проверяет?** 28 чистых предметных функций: валидацию, фильтры, статистику, операции, неизвестные id, пустые наборы, отсутствие мутаций. Не запускает React, не проверяет JSX, доступность, браузер и сборку — для этого есть ручной протокол и `npm run build`.
15. **Что изменится при подключении API в ПР8?** Вместо `data.js` — `loadInitialData` через `useEffect` и `AbortController`; вместо локальных `addTask`/`updateTask` — HTTP-методы; id назначает сервер; фильтры уходят в query; `onSave` станет `Promise<boolean>`; статистика будет считаться по последней полученной выборке, а не по всему набору.
