## Организация кода

`task-service.js` — операции модели: создание, поиск, статистика, добавление, статус, удаление и новое `updateTask`; модуль не знает ни о DOM, ни о хранилище. `form-validation.js` — чистая проверка черновика формы: нормализует id и название, проверяет уникальность и приоритет, возвращает `{ ok, value }` либо `{ ok, errors }` по полям, не обращаясь к DOM. `task-storage.js` — граница `localStorage`: сериализация `{ version: 1, tasks }`, проверка полной схемы при чтении, перехват исключений getItem/setItem/removeItem. `task-view.js` создаёт карточки (три кнопки) и сводку через `textContent`, не меняя данные. `main.js` хранит текущее состояние (`currentTasks`, `currentFilter`, `editingId`), координирует валидацию → сервис → сохранение → отрисовку.

Функции хранения получают объект `storage` аргументом, чтобы модуль можно было проверять подставным хранилищем и явно показать внешнюю зависимость; глобальный `localStorage` используется только в `main.js`. Данные из JSON проверяются до использования, потому что успешный `JSON.parse` гарантирует только синтаксис: значение может оказаться числом, объектом другой версии или списком с повторяющимися id. Некорректная запись не используется частично — приложение берёт независимую копию исходного набора и показывает предупреждение.

## Отладка и клавиатура

Точка останова — `handleFormSubmit` (строка вызова `validateTaskDraft`). Для добавления задачи `20` / «  Изучить localStorage  » / high: сырой `draft` = `{id: "20", title: "  Изучить localStorage  ", priority: "high"}`; результат `validateTaskDraft` = `{ok: true, value: {id: 20, title: "Изучить localStorage", priority: "high"}}`; результат `addTask` = `{ok: true, tasks: [...]}`; записанная строка JSON — в `Application → Local Storage → tip-js-practice-04:demo`. Ошибочный сценарий повторного id: `validation.ok = false`, `errors.id = "Задача с id 4 уже существует"`, список и запись не изменились.

Клавиатура: Tab проходит поля id → название → приоритет → кнопка; Enter в поле названия отправляет форму без перезагрузки страницы (`preventDefault`); Space активирует кнопки карточек; фокус при начале редактирования — в поле названия, после отмены — в поле id.

## Вывод

Реализованы форма создания и редактирования с двумя уровнями проверки ввода и сохранением списка в `localStorage`. Нативная проверка HTML (`required`, `min`, `step`, `maxlength`) даёт мгновенную обратную связь и клавиатурное поведение, но не знает правил предметной области — их закрывает чистая прикладная валидация (`validateTaskDraft`): уникальность id, `trim`, допустимый приоритет, существование редактируемой задачи. Третий уровень — проверка прочитанных из хранилища данных по полной схеме (`version`, поля задач, уникальность id): корректная запись восстанавливается, повреждённая заменяется независимой копией исходного набора с предупреждением. Все операции модели возвращают новый массив, вход не изменяется; отрисовка не обращается к хранилищу; сохраняются только изменения модели. Из ошибок исправлены: {{перечисли свои, например: потеря successMessage из-за порядка вызова setFormMode; пустой список случайно откатывался к исходному набору}}. После расширения (черновик) все автоматические проверки остаются зелёными.
